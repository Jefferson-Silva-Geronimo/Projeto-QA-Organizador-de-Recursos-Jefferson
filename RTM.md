# Matriz de Rastreabilidade de Requisitos (RTM)

Fonte dos requisitos: [especificação do projeto](https://afonsolelis.github.io/aulas_senac/pages/qualidade2/especificacao-projeto.html).

## Como ler

- Há uma linha por requisito funcional (RF-01 a RF-16) e uma linha por regra de negócio (RN-01 a RN-33).
- Nas linhas de RF, a coluna Requisito traz o RF e a coluna Regra traz as RN ligadas. Nas linhas de RN, a coluna Regra traz a RN e a coluna Requisito traz os RF ligados.
- **crítico:** critério explícito. Uma regra é crítica se for uma das regras críticas da especificação (RN-01 a RN-08, seção 4). Um RF é crítico se, na matriz de [requisitos-funcionais.md](docs/prd/requisitos-funcionais.md), estiver ligado a pelo menos uma dessas regras. Por esse critério são críticos 12 dos 16 RF: RF-01, RF-03 a RF-10, RF-12, RF-13 e RF-16. Meta da especificação: 100% dos requisitos críticos na RTM.
- Risco: identificador R-xx definido em [plano-de-teste.md](docs/plano-de-teste.md), seção 8. É risco inicial, a refinar.
- Cenário: preenchido na Fase 2 com os CEN-xx de [ciclo-00.md](docs/avaliacao-arquitetural/ciclo-00.md). Linha sem cenário de qualidade fica vazia e é coberta por caso de teste funcional na Fase 4. Caso de teste: preenchido na fatia 4.0 com os CT-xxx de [casos-de-teste.md](docs/testes/casos-de-teste.md). Evidência (Fase 4): classes de teste que contêm os CT da linha, achadas pelo nome do método (`ctNNN`) ou pela etiqueta `@CT-NNN` da feature, mais a execução de referência E-1. Status: **testado** só quando todo CT da linha tem teste existente e a execução E-1 está verde; **parcial** quando falta teste ou a cobertura do back end não esgota o requisito; **não testado** quando a linha não tem CT.

- RF-15 e RF-16 são acréscimos da equipe. RN-09 em diante são decisões da equipe.

**Execução E-1:** `./mvnw -B clean verify` local em 17/10/2026, com PostgreSQL 17 fixado por digest: 468 testes (136 de unidade e arquitetura, 332 de integração e BDD), 0 falhas, gate do JaCoCo cumprido (96,7% de linhas, 84,6% de branches). **Execução E-2 (CI):** run `39055557492` do PR 2, check `test` verde, com os commits desta sessão.

**Execução E-3 (Fase 6, 18/10/2026):** `./mvnw -B clean verify` local depois das mudanças do back end para o front end (F6-06): 515 testes (154 de unidade e arquitetura, 361 de integração e BDD), 0 falhas, gate do JaCoCo cumprido (96,8% de linhas, 85,0% de branches). Uma execução anterior, idêntica no código, teve 1 falha em `NotificacaoApiIT.int01ECt103` (esperava 2 envios); a classe passou isolada e a execução seguinte passou inteira. Causa não determinada, registrada em [ocorrências a vigiar](docs/testes/ocorrencias-a-vigiar.md), sem alteração de teste.

**Execução E-4 (front end, 18/10/2026):** em `frontend/`, `npm ci`, `npm run gerar:api` sem divergência do contrato, `npm run lint`, `npm run typecheck`, `npm test` (16 arquivos de teste, 237 testes, 0 falhas) e `npm run build`, todos com saída 0. Os testes de componente não usam banco; a API é simulada na fronteira do `fetch`.
